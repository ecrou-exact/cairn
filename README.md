# Cairn

Cairn is a self-hosted workspace for open-source developers. It keeps every task with its context, shows the plan as a graph, runs coding agents on several tasks in parallel under your control, and keeps GitHub items and local instances one click away.

> **Status:** early development (Phase 2 of 11, foundations). The full specification is in [`PROJECT_BRIEF.md`](PROJECT_BRIEF.md) and progress in [`docs/PROGRESS.md`](docs/PROGRESS.md).

## What works today
- Single-owner account: first-run setup, sign-in, two-factor sign-in (TOTP, codes cannot be replayed), password change that signs out other sessions.
- Secrets vault: values encrypted with AES-256-GCM; the master key lives in the OS keyring, in an environment variable or in an owner-only key file, never in the database.
- Security by default: bound to `127.0.0.1`, deny-by-default access rules, CSRF protection, rate-limited sign-in, strict Content Security Policy (no inline script or style, no eval), activity log of every sensitive action.
- Four colour themes built on design tokens (Stone, Basalt, Moss, Ember, plus Auto).

## Getting started
Requires Python 3.12+ and [uv](https://docs.astral.sh/uv/). Works on Linux (Ubuntu is the reference), macOS and Windows.

```bash
git clone https://github.com/ecrou-exact/cairn.git
cd cairn
uv sync
uv run python manage.py setup    # creates .env, the master key and the database
uv run python manage.py start    # http://127.0.0.1:7010
```

Open the URL, create the owner account, then turn on two-factor sign-in under **Security**.

## Commands
| Command | What it does |
|---|---|
| `python manage.py setup` | First run: `.env` with a secret key, master key, database |
| `python manage.py start` | Development server with auto-reload |
| `python manage.py serve` | Production server (gunicorn on Linux/macOS, waitress on Windows) |
| `python manage.py upgrade` | Apply database migrations |
| `python manage.py migrate "message"` | Create a migration after a model change |
| `python manage.py test` | Run the test suite |
| `python manage.py check` | Lint, security scan and tests |

## Configuration
Environment variables (or `.env`):

| Variable | Default | Purpose |
|---|---|---|
| `CAIRN_SECRET_KEY` | generated by `setup` | session signing key |
| `CAIRN_ENV` | `development` | `development`, `production` or `testing` |
| `CAIRN_HOST` / `CAIRN_PORT` | `127.0.0.1` / `7010` | listen address |
| `CAIRN_DATABASE_URL` | SQLite in the data directory | e.g. `postgresql+psycopg://…` (install with `uv sync --extra postgres`) |
| `CAIRN_DATA_DIR` | OS data directory (`~/.local/share/cairn` on Linux) | database, key file, uploads, worktrees |
| `CAIRN_MASTER_KEY` | OS keyring or key file | vault master key (urlsafe base64, 32 bytes) |
| `CAIRN_HTTPS` | `0` | set to `1` behind HTTPS to mark cookies `Secure` and send HSTS |

## Security
Cairn controls credentials and runs commands on your machine, so security comes first. Read [`docs/SECURITY.md`](docs/SECURITY.md) for the threat model. Do not expose Cairn to a network without HTTPS and two-factor sign-in.
