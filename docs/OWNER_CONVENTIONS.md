## 2. Code organisation

```
app/
  __init__.py            app factory
  api/<feature>_api.py   REST resources (thin)
  core/
    db_class/<feature>.py   SQLAlchemy models, one module per feature
    utils/                  decorators, logger, settings, helpers
  features/<feature>/
    <feature>.py            blueprint (routes only: decorator + call core)
    <feature>_core.py       all logic and DB access
  templates/<feature>/      one folder per feature
  static/
    css/core.css            only truly global tokens/classes
    css/components/         CSS of reusable components
    css/<feature>/          CSS of one feature
    js/components/          reusable Vue components (ES modules)
    js/<feature>/           feature-specific JS
  config/<key>.json         settings (defaults)
tests/<feature>/            mirrors features/
```

Rules taken from flask-launchpad's and Rulezet's `CLAUDE.md`:
- No DB access and no logging in routes: **route → core**. Core is the only implementation, reused by API, MCP tools, modules and jobs.
- Every route has a decorator; no naked route.
- Every mutating action calls `log_action` in core (create, edit, delete, restore, bulk…).
- Every HTML feature that reads or writes data has a matching API endpoint.
- Soft delete from user actions; hard delete only from the trash.
- Reuse components before creating new ones; a reusable component never lives in a feature folder and vice versa; same folder name in templates / js / css.
- No inline `<style>`/`<script>`, no hard-coded colours (tokens only), no `console.log`, no `| safe` on user data.
- A component rendered once per row never fetches on mount (shared module-level promise).
- Toasts through one `create_message()` helper; one shared pagination component; confirm dialogs through the app's own component, never `confirm()`.
- Static files always through `url_for('static', …)` (versioned, immutable cache).
- Configuration values live in settings files, not in code; only values the code branches on stay constants.
- Run `bandit -r app/` and the test suite before declaring a change done.

## 3. UI patterns
- Page = banner (icon, title, accent line, short description, breadcrumb inside) + cards.
- Lists offer **table or cards**, default chosen in user settings; sort/filter/pagination **server-side**; filters, sort, page and view kept in the URL; clickable tags add themselves to the filter; a Clear button appears when a filter is active; sticky table header (Flowintel #331).
- Loading: skeleton immediately, animated logo after ~100 ms (Flowintel `loading_overlay` / `flow_loader`).
- Several themes driven by CSS variables (flask-launchpad has seven themes and a Theme Studio).
- Per-user preferences: theme, navigation layout, toast position/duration, default list view.

## 4. Git, commits, PRs, issues
- **Commit messages:** gitchangelog style `<type>: [<scope>] <message>`, types `new` / `add` / `chg` / `fix` (Rulezet, flask-launchpad, project-graph, mmdb-server). The message is a full sentence and may be long and descriptive; it says what the user gets. Example: `fix: [ui] menu navigation and settings polish`.
- **Branches:** `main` + `development` in Rulezet / flask-launchpad; feature branches named after the topic (`tags-misp-style`, `rulezet-integration`, `small-fixes`).
- **PR titles:** plain English summary of the outcome, often `Area: what changes` (`Tags: MISP v3 style`, `Web: capture page redesign, part 1 (…)`); split big work into numbered parts; `(WIP)` while open.
- **PR bodies:** `## What changes`, then bold sub-headings per area (`**Case index (/case/)**`), bullet points written as facts, migrations named with their id, screenshots after each area.
- **Issues:** title in commit style (`new: [rule] cross-format rule families`); body = short user-facing description, bullet list of what the user sees, "Builds on …" with linked issues, link to the plan in `docs/future/…`.
- **Plans** live in the repo (`docs/future/<topic>.md`, `docs/design/…`, `ROADMAP.md`).
- **No AI attribution** in this repository and in every repository the app manages — no `Co-Authored-By: Claude`, no "Generated with…". Some upstream projects (Flowintel `AGENTS.md`) allow or require it; the app must follow each managed repo's own rules **except** that the owner's hard rule wins for the owner's commits. To confirm with the owner per project.
- Commit identity: `ecrou-exact <ecrou-exact@users.noreply.github.com>`; the owner's personal e-mail never appears in commits or public files.

## 5. Docs style
- README: short pitch, screenshot, "Getting started" with commands, a commands table, features with one screenshot each, project structure tree, link to the developer reference (`CLAUDE.md`).
- `CLAUDE.md`: dense, rule-first, lists every component with its path and props; updated after every feature.
- English for code, UI text, docs, commits and PRs.
